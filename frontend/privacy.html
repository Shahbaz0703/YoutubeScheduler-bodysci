📌 1. Overview & Architecture

YouTube Shorts Scheduler is an open-source, personal automation workflow designed to schedule and publish video content directly to the user's authenticated YouTube channel.

The software consists of a static dashboard hosted via GitHub Pages and backend automation scripts executed locally or via private GitHub Actions workflows. There is no third-party cloud database, no centralized tracking server, and no commercial data aggregation.

🔍 3. Information We Access & Collect

The application accesses only the minimum necessary data required to upload and schedule videos on behalf of the channel owner:

  • Google OAuth 2.0 Credentials: Client ID, Client Secret, and Refresh Token generated through the Google Cloud Console by the user.
  • API Scope Requested: https://www.googleapis.com/auth/youtube.upload — used exclusively to upload video files to YouTube and configure metadata (title, tags, description, privacy status, and scheduled publish time).
  • Local Video Files & Metadata: Video files located in the repository's /videos directory, and schedule timestamps stored in data/videos.json and data/upload-state.json.
  • API Response Data: The uploaded YouTube Video ID and URL returned by the YouTube Data API upon successful upload, recorded locally in data/upload-state.json to prevent duplicate uploads.

Information We Do NOT Collect: We do NOT collect your name, email address, password, browsing history, financial information, payment details, or personal YouTube viewing history.

⚙️ 4. How Information Is Used

Information accessed by the application is used strictly for the following functional purposes:

  1. Authenticating with the YouTube Data API v3 on behalf of the user's authorized Google Account.
  2. Transmitting video binary streams and metadata (title, description, tags, scheduled publish timestamp) to YouTube servers.
  3. Updating the local upload log (data/upload-state.json) so that the queue advances and previously uploaded videos are skipped.

Under no circumstances is user data or Google API data used for advertising, marketing, profiling, or training automated machine learning models.

🛡️ 5. Storage, Security & Zero-Telemetry

ShortsScheduler operates under a zero-telemetry, client-owned data model:

  • Encrypted GitHub Secrets: In automated GitHub Actions workflows, OAuth tokens (YOUTUBE_CLIENT_ID, YOUTUBE_CLIENT_SECRET, YOUTUBE_REFRESH_TOKEN) are stored in your private GitHub repository secrets, which are encrypted using Libsodium before being saved.
  • Local Environment Files: For local runs, tokens reside solely in the user's local .env file, which is ignored by Git via .gitignore and never pushed to public repositories.
  • Static Frontend Dashboard: The frontend hosted on GitHub Pages is entirely static (HTML/CSS/JS) and does NOT contain, transmit, or expose any API keys, client secrets, or OAuth tokens.
  • No External Servers: No analytics cookies, tracking pixels, or third-party monitoring scripts are embedded in the application.

🚫 6. Third-Party Data Sharing & Sale

✅ Strict No-Sale & No-Transfer Policy

We do NOT sell, rent, trade, lease, or transfer your personal data or Google user data to any third party for any commercial or non-commercial purpose.

The only external communication occurs directly between the user's execution runner (local machine or private GitHub Actions virtual machine) and official Google API endpoints (googleapis.com) via encrypted HTTPS connections.

🗑️ 7. User Control, Revocation & Data Deletion

You retain 100% control over your credentials and channel access at all times:

How to Revoke Application Access:

You can immediately revoke ShortsScheduler's access to your Google Account at any time through Google's official security interface:

🔗 Google Account Security Settings

Visit https://myaccount.google.com/permissions, locate the authorized application or project, and click “Remove Access”. This instantly invalidates all refresh tokens and blocks further API requests.

How to Delete Local Data:

  • Delete your local .env file containing OAuth credentials.
  • Remove repository secrets from your GitHub repository settings under Settings → Secrets and variables → Actions.
  • Delete the repository or clear data/upload-state.json to remove all historical upload logs.
